# niri-config

quhongbin's [niri](https://github.com/YaLTeR/niri) scrollable-tiling Wayland
compositor configuration, packaged as a Nix flake with a home-manager module.

## Layout

```
.
├── flake.nix              # entry point — produces homeConfigurations.quhongbin
├── sync-from-system.sh    # copy ~/.config/niri/ back into the repo
├── niri/
│   ├── default.nix        # home-manager module: enables niri + companion pkgs,
│   │                      # links config.kdl into ~/.config/niri/
│   ├── config.kdl         # the niri config the compositor reads
│   └── dms/               # reference snapshots of DMS-generated fragments
│       ├── alttab.kdl
│       ├── binds.kdl
│       ├── colors.kdl
│       ├── cursor.kdl
│       ├── input.kdl
│       ├── layout.kdl
│       ├── outputs.kdl
│       ├── windowrules.kdl
│       └── wpblur.kdl
└── README.md
```

## Prerequisites

1. **Nix with flakes enabled.** Add to `~/.config/nix/nix.conf`:
   ```ini
   experimental-features = nix-command flakes
   ```
   If that file does not exist yet, create it.

2. **home-manager.** Easiest is to run it through the flake (`nix run home-manager`),
   which fetches a pinned copy — no system-wide install needed.

## Apply

From the repo root:

```sh
home-manager switch --flake .#quhongbin
```

That:

- installs `niri` and the helper packages the binds assume (`alacritty`,
  `fuzzel`, `waybar`, `swaylock`, `swayidle`, `brightnessctl`, `playerctl`,
  `wireplumber`, `pipewire`, `grim`, `slurp`, `wl-clipboard`),
- registers a `niri.desktop` session entry so display managers can offer it,
- links `niri/config.kdl` into `~/.config/niri/config.kdl`.

The `dms/` fragments are **not** managed by home-manager — see below.

To preview without switching, dry-run with:

```sh
nix build .#homeConfigurations.quhongbin.activationPackage
```

## Edit workflow (one-way by design)

The repo is the source of truth. **Edit there, then apply:**

```sh
$EDITOR niri/config.kdl            # edit in repo
home-manager switch --flake .      # deploy to ~/.config/niri/
niri msg action load-config        # hot-reload, no session restart
```

If you edit `~/.config/niri/` directly, the next `home-manager switch` will
overwrite your changes.

### Going the other way (system → repo)

If you (or a tool) edited files in `~/.config/niri/` and you want to capture
them into git, run:

```sh
./sync-from-system.sh
git diff
git add -A && git commit
```

## Customizing

- **Username / home directory** — edit `flake.nix` (`username` and
  `homeDirectory`). Defaults to `dev` / `/home/dev`.
- **Binds / layout / outputs** — edit `niri/config.kdl`. After editing, re-run
  `home-manager switch --flake .#quhongbin` and reload niri with
  `niri msg action load-config` (or restart the session).
- **Extra packages** — append to `home.packages` in `niri/default.nix`.

## About `niri/dms/`

The files under `niri/dms/` are reference snapshots of what
[DankMaterialShell](https://github.com/AvengeMedia/DankMaterialShell)
generates at runtime. They start with `// ! AUTO-GENERATED BY DMS — DO NOT
EDIT !`, and DMS writes its own copies to `~/.config/niri/dms/` whenever it
runs.

Because of that, `niri/default.nix` deliberately does **not** link them into
`xdg.configFile` — otherwise home-manager and DMS would clobber each other on
every switch.

To refresh the repo's snapshots after DMS regenerates them:

```sh
./sync-from-system.sh
git add niri/dms/ && git commit
```

## Initializing the GitHub repo

This repo is initialized locally with a placeholder remote. After creating the
repo on github.com (e.g. `quhongbin/niri-config`), point the remote at it:

```sh
git remote remove origin   # if a placeholder was added
git remote add origin git@github.com:quhongbin/niri-config.git
git push -u origin main
```

## Notes on the current config

`config.kdl` is mostly upstream defaults: gaps 16, focus ring enabled, border
disabled, default column widths of 1/3, 1/2, 2/3, waybar spawned at startup,
and the standard niri bind set (Mod+T alacritty, Mod+D fuzzel, Mod+Q close,
vim-style focus/move, etc.).

The active eDP-1 output block is currently commented out with `/-` — uncomment
it once you have confirmed the correct `mode` and `position` for your display
with `niri msg outputs`.
